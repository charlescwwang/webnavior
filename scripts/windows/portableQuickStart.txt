第一次使用，只要做三件事
1. 將整個 ZIP 解壓縮到 C:\Webnavior-Kiosk。不要直接在 ZIP 裡執行。
2. 雙擊「Webnavior Kiosk.exe」。不需要 Setup、Build、Node 或 pnpm。
3. 選擇現場區網、Tailscale 或公開網域，再依畫面建立／配對設備。

請保留 EXE 旁的所有檔案與資料夾，不能只複製 EXE。
現場區網：http://172.17.69.17:5169/kiosk/（須能連到現場主機）
Tailscale 內網：http://100.92.1.80:5169/kiosk/（需先連上 Tailscale）
公開網域：https://webnavior.aikcitri.qzz.io/kiosk/（一般網際網路）
每次啟動先選擇本次連線；不會在點餐途中自動切換。

如何修改設定
先關閉程式，再雙擊「Edit Settings.cmd」，修改 kiosk.settings.json，儲存後重開 EXE。
一般使用不用改，網址已設定為：
http://172.17.69.17:5169/kiosk/

kioskUrl：啟動時預選的網址，必須與 connections 內其中一項 url 一致。
connections：啟動選單，逐項修改 label（名稱）與 url（網址）；網址最後保留 /kiosk/。
修改 IP 時，記得同時修改預選 kioskUrl 與對應的 connections[].url。
只改設定後重開即可，不用重新打包。不可將舊版設定檔直接蓋掉新版；新版需要 connections。
伺服器也須在 KIOSK_TRUSTED_ORIGINS 設定新 origin，並重啟 API；只改 EXE 不會替後端開放來源。
例如 http://172.17.69.17:5169（不要加 /kiosk/）。
windowed：true 是一般視窗；false 是全螢幕 Kiosk。布林值不用加引號。
diagnosticPort：保持 0。只有工程師協助檢查時才改，完成後改回 0 並重開。

對話模型、ASR、TTS 與 API Key 都在伺服器後台設定，不填在這台電腦：
https://webnavior.aikcitri.qzz.io/admin/system/models
可以雙擊「管理後台.url」開啟；語音模式依後台實際配置。

如何關閉
一般視窗按右上角 X；全螢幕可按 Alt+F4。

3. 使用新版設定格式，再手動套用自己的視窗／入口設定；預設為現場 172.17.69.17。

資料保存在 %LOCALAPPDATA%\Webnavior\Kiosk-Pilot。不要刪除這個資料夾。

遇到問題
・程式提示設定錯誤：檢查 JSON 的逗號、雙引號及 true/false，或還原包內範例設定。
・網站打不開：先用瀏覽器開上面的網址，確認公司網路或 Proxy 可連線。
・第一次可能要允許 Windows 使用麥克風與相機；在設定選擇實際設備。
・公司安全政策阻擋程式時，請交給資訊人員核對來源、SHA256 及公司政策。
  本包尚未做程式簽章，請勿為此永久降低安全設定或停用防毒。
・舊版 PowerShell 的 stdout 版本檢查錯誤不適用這個可攜版，EXE 不經該步驟啟動。
・本包已做原生子程序、瀏覽器測試、PE 相依及封包雜湊驗證；Windows 實機的麥克風、
  相機、觸控與真實點餐仍須在目標機器測試。Build 成功不代表實機全部驗收。

自建 PB 統一連線公開 HTTPS 測試站，不使用 Windows 的 127.0.0.1。
網頁版備援：用瀏覽器開公開 Kiosk，選擇自建 PB；正式 PB 點餐請使用 EXE。
區網 HTTP 入口的普通瀏覽器不具備 EXE 的安全來源特例，備援請用 HTTPS。

Hush CPU 收音
・此方案已移除 AEC 與播放參考配對；原生麥克風直接進入 RTF／MVDR → Hush → AGC → VAD。
・喇叭播放可能再次被麥克風收到；原 LCMV／Spatial Mask 的 AEC 設定不變。
・內含 Python、Hush 原生函式庫與模型，EXE 自動管理；不用安裝 Python 或另開服務。
・需要配套的 Kiosk 前端與完整 EXE（0.7.5／native bridge v9）。
・到麥克風設定選 UMA-8 → 線上 RTF／MVDR＋Hush CPU → 套用收音方式。
・選擇原生裝置、確認七路映射與增益，再套用；原 LCMV／Spatial Mask 可隨時明確選回。
・Hush 降噪組合可選推薦 A（20 dB／30% MVDR 原音）、推薦 B（20 dB／10% 原音）及原始對照（100 dB／0%）；選好後按「套用音訊設定」。
・參數只在下一次收音串流套用，不會每句重設。兩組是比較起點，須用相同錄音與店內環境實測。
・舊 GPU 選項已移除，若原本選用該方案，請重新選擇並套用；不會自動改成 Hush。
・喇叭使用原本獨立設定。TTS、提示音與等待音樂的實際播放音訊供 AEC 消回音。
・流程：重採樣 → AEC3 → 共同增益 → RTF／MVDR → Hush CPU → AGC → VAD → 現有 ASR。
・切換請在未說話時進行，未完成的語句會丟棄；初始化或積壓失敗不自動改用其他模型。
・Test Hush Audio.cmd 可做選用的無喇叭管線診斷，輸出 Hush-Audio-Test.json，不保存錄音。
・先測管理員收音與 TTS 插話，再退出管理模式測正常接待；至少測 30 分鐘實際運行。
・此為待 Windows 實體驗收的試用包，不含 GPU 音訊測速或略過 UL-UNAS 的啟動器。

連線與後台
・三入口共用同一套 API／資料庫；Kiosk API 隨本次所選入口連線。
・不同 origin 的設備 Cookie 各自保存，首次切換需另外配對，不搬移其他機器的登入。
・現場 HTTP 僅 EXE 有相機／麥克風安全來源特例；瀏覽器完整影音備援仍請用 HTTPS。
・完整網頁管理後台捷徑仍保留公開 HTTPS；EXE 內 PIN 技術設定可走現場／Tailscale。
・內網入口不代表全系統離線：公開 PB 測試站與外部模型服務仍需各自的網路。
・現場 IP 建議由網管設定 DHCP 固定租約；其他機器需可連 TCP 5169。
