## 依產品版本回復整組服務

「回到 0.7.8-rc.7」指回到 RC7 發布時搭配的整組版本。Web 是 11 月 20 日的 `web-falcon-removal-20261120-r1`，Kiosk 與 Windows 使用 RC7，API 使用 RC8 變更前的付款設定。管理端可從 `pb-test.local/web-merchant-id-20261124-r1/backup/` 取得該版入口，SHA-256 為 `04b0fb10af125732e1af67a7853d2e966c265ddccc819fe810f323a6c7beaf40`。歷史 Web 版號檔曾落後於入口，以該發布清單核對資源，回復後讓兩端的 `version.json` 均標示目標產品版本。Windows 與 API 的操作見下方。

從 RC8 起，Web、Kiosk 前端、Windows 可攜包及 Git 標籤共用桌面套件的版本號，例如 `0.7.8-rc.8` 與標籤 `v0.7.8-rc.8`。每次發布在同一份版本紀錄登記各端實際組件、安裝包校驗碼與前一個產品版本。部署批次名稱僅供找備份使用。切換後核對 Web、Kiosk 的公開版本與 EXE 安裝包清單。

## 僅回復管理後台

1. 確認正式管理端 `/version.json` 的產品版本是 `0.7.8-rc.8`，部署批次是 `web-v2026.11.24.2`。從 `pb-test.local/web-v2026.11.24.2/backup/` 取出 `version.json` 和 `index.html`，用發布清單 `publish-plan.json` 的 `before` 雜湊核對。
2. 確認舊版所需的靜態檔案仍在。將兩檔原子替換回 `/var/www/airi/web/`，最後切換 `index.html`。保留版本化資源，讓已開啟的頁面可繼續載入。
3. 從正式網址核對版本與入口載入的資源，重新開啟「互動體驗 → 設定點餐網站」確認別名直接展開。既有店家設定保留。

## 回復 Kiosk 付款整組

1. 安排機台停止接新單，等進行中的付款結束。確認線上 Kiosk 與 API 對應 RC8，另存當下狀態供復原。
2. `pb-test.local/kiosk-rc8-20261124-r1/` 內的 `api-plan.json` 列出兩個付款相關檔案的實際執行路徑及前後雜湊。核對線上檔符合 `after`，把 `api-before/` 內的兩個原檔依路徑原子還原，再重新啟動 `webnavior-api.service`，確認 `/readyz` 的 db 和 redis 均為 ok。
3. 核對 `before-activation/` 兩檔符合 `release.json` 的 `before` 雜湊，確認 RC7 靜態資源仍在。將 `version.json`、`index.html` 依序原子還原至 `/var/www/airi/kiosk/`。從現場使用的網址與公開網址確認 `/kiosk/version.json` 為 `kiosk-rc7-20261123-r1`。
4. 核對 `previous-latest-windows-portable.json` 指定的 RC7 ZIP 與 SHA-256，再原子還原最新下載指標 `/tmp/latest-windows-portable.json`。已安裝 RC8 的 Windows 機台須完全退出 Kiosk，將 RC7 ZIP 整包解壓到新資料夾並啟動其中的 EXE。保留原有裝置設定與登入資料。
5. 現場核對機台版本、點餐入口與付款畫面，記錄回復時間及驗收結果。回溯軟體不涉及取消訂單、退款或還原資料庫。
