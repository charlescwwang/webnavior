# 點餐 Kiosk 的購物車位置與訂單覆核研究

研究日期：2026-09-23

> 範圍限定為點餐時「訂單目前有什麼」的可見性、購物車入口與訂單覆核；不討論
> 推薦、付款或結帳轉換。本筆記優先採餐飲 POS／Kiosk 官方文件；官方公開資料多
> 說明互動流程而非提供位置 A/B 實驗，因此結論是針對 AIRI 螢幕的設計推論，不是
> 對所有裝置的通用定律。

## 目前頁面的判讀

`apps/order-menu/src/App.vue` 在標頭右上顯示不可操作的 `購物車 n 項 · 金額` 提示，
但完整 `cart-panel` 被放在所有分類與品項區塊之後。顧客在長菜單中新增品項後，必須
捲到頁面底部才可檢視、修改或送出訂單。因此它目前是「頂端提示＋頁尾訂單」，不是
持續可用的訂單摘要。

## 官方模式與證據

| 官方產品 | 可驗證的購物車／覆核流程 | 對版位的訊號 |
| --- | --- | --- |
| Square Kiosk | Square 表示點餐者持續加點時 cart 會保持可見；品項加入 `Your order` 後仍可重新開啟修改加料／尺寸、移除單項或清空。產品更新也將 Kiosk 改版列為包含 **always-visible carts** 與較寬的品項 modal。 | 在瀏覽期間至少應持續看見「訂單數量／金額／進入訂單」；可見的是摘要，不表示每一筆明細都要永久佔住版面。 |
| Toast Self-Ordering Kiosk | 點餐主畫面讓顧客在左側捲動 menu groups、右側瀏覽項目；點品項後，詳情 pane 從**右側**滑出。顧客準備覆核時，點畫面**底部**的 `View order`；`My Order` 畫面才提供數量增減、移除與重新編輯品項。 | Toast 將右側留給暫時性的品項決策，將「整筆訂單」設為底部的持續入口與獨立覆核畫面。這是避免右欄同時競爭品項詳情、菜單與完整購物車的明確範例。 |
| Toast Kiosk 設定 | Toast 可切換顯示品項描述；開啟後列表每列為兩欄，關閉描述則可為五欄。 | Kiosk 的可閱讀品項卡與可用瀏覽空間有直接取捨。若 AIRI 右側長駐完整訂單，會再壓縮品項網格；不宜把「資訊永遠可見」誤做「完整明細永遠可見」。 |

## 對桌上型／橫向 Kiosk 的結論

| 方案 | 適配度 | 結論 |
| --- | --- | --- |
| 右側長駐完整購物車 | 低到中 | 適合不需要右側品項詳情、且螢幕極寬的 POS 型操作台；不適合 AIRI 預計的分類導覽＋品項網格＋右側詳情，三者會爭奪橫向寬度。官方 Toast 流程也把右側作為項目詳情的暫時 pane。 |
| 標頭右上小圖示／數字 | 中 | 可當輔助提示，但若不能直接開啟／覆核訂單，無法解決「知道有幾項，卻看不到有哪些」；不能單獨採用。 |
| 底部固定的訂單摘要列 | **高（建議）** | 最接近 Toast 的 Kiosk 入口，同時符合 Square 要求的持續可見。列內保持固定、易觸控的 `目前訂單 · n 項 · 金額 · 查看訂單`；不遮蔽品項卡，也不與右側詳情衝突。 |
| 可拖曳／可移動的浮動購物車 | 低 | 沒有找到主流餐飲 Kiosk 官方文件將它作為模式。它會引入位置記憶、遮住商品與回復預設位置的成本，卻無法改善第一位顧客的可發現性；不建議作為第一版。 |

## 建議的 AIRI 互動分層

```text
瀏覽／選品
┌─────────────────────────────────────────────────────┐
│ 分類導覽 │ 品項網格                          │（右側品項詳情）│
├─────────────────────────────────────────────────────┤
│ 目前訂單  3 項 · $285                         [查看訂單] │  ← 固定底列
└─────────────────────────────────────────────────────┘

覆核（點「查看訂單」）
┌─────────────────────────────────────────────────────┐
│ ← 繼續點餐                我的訂單                      │
│ 餐點、客製、數量、單價                    [編輯] [移除] │
│ …                                                   │
│ 合計                                           下一步 │
└─────────────────────────────────────────────────────┘
```

1. **瀏覽層只顯示摘要。** 固定底列在空車時顯示「尚未選擇餐點」，首次新增時以簡短
   動效與即時 `aria-live` 訊息確認已更新；之後始終保留項數、合計與可點的覆核入口。
2. **品項層只處理一個餐點。** 詳情／客製面板可從右側滑入，完成後關閉並回到原本分類
   與捲動位置；不要在該面板同時塞完整購物車。
3. **訂單層才給完整編輯。** `查看訂單` 開啟獨立覆核畫面（或行動裝置的全高 bottom
   sheet），讓數量、移除與重新客製有充足空間；返回後仍回到先前的瀏覽位置。
4. **不做可移動浮窗。** 螢幕位置由版面決定，讓新客不必先找購物車，也避免浮窗遮住
   大型觸控目標。

此結構將「持續知道訂單狀態」與「需要時完整審閱訂單」分開。它不預先決定後續的
推薦內容或結帳步驟，只為兩者保留清楚的入口。
